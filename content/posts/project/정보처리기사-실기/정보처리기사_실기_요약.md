## 요구사항 확인

### 소프트웨어 생명주기

소프트웨어를 개발하기 위한 설계, 운영, 유지보수 등의 과정을 단계별로 나눈 것이다.

| 모델 | 핵심 내용 |
| --- | --- |
| 나선형 모델 | 여러 번의 개발 과정을 거쳐 점진적으로 개발한다. `계획 수립 -> 위험 분석 -> 개발 및 검증 -> 고객 평가` 순서로 진행한다. |
| 폭포수 모형 | 이전 단계로 돌아갈 수 없다는 전제 아래 각 단계를 확실히 매듭짓고, 결과를 검토 및 승인한 뒤 다음 단계로 진행한다. |
| 애자일 모형 | 고객 요구사항 변화에 유연하게 대응하기 위해 고객과의 소통에 초점을 둔다. |

### 애자일

#### 핵심 가치

- 프로세스와 도구보다 개인과 상호작용
- 포괄적인 문서보다 작동하는 소프트웨어
- 계약 협상보다 고객과의 협업
- 계획을 따르기보다 변화에 반응

#### 스크럼

| 활동 | 설명 |
| --- | --- |
| 스프린트 계획 회의 | 제품 백로그 중 이번 스프린트에서 수행할 작업을 대상으로 단기 일정을 수립한다. |
| 스프린트 | 실제 개발 작업을 진행한다. 보통 2~4주 단위로 수행한다. |
| 일일 스크럼 회의 | 매일 진행 상황을 점검한다. 번다운 차트를 활용한다. |
| 스프린트 검토 회의 | 제품이 요구사항에 부합하는지 테스트한다. |
| 스프린트 회고 | 규칙 준수 여부와 개선점을 확인하고 기록한다. |

#### XP

- 고객 참여와 개발 과정의 반복을 극대화하여 요구사항 변화에 유연하게 대응한다.
- 짧고 반복적인 개발 주기, 단순한 설계, 고객의 적극적인 참여를 통해 빠른 개발을 지향한다.
- 핵심 가치: 의사소통, 단순성, 용기, 존중, 피드백

| Collective Ownership | 개발 코드에 대한 권한과 책임을 공동으로 소유한다. |
| Test-Driven Development | 테스트를 먼저 작성하고 구현한다. |
| Whole Team | 모든 구성원이 각자의 역할과 책임을 가진다. |
| Continuous Integration | 모듈 단위로 개발한 코드를 지속적으로 통합한다. |
| Refactoring | 프로그램을 쉽게 이해하고 수정할 수 있도록 개선한다. |
| Small Release | 짧은 주기로 릴리스하여 요구 변화에 빠르게 대응한다. |

### 소프트웨어 공학

소프트웨어 위기를 극복하기 위한 방안이다.

- 현대적인 프로그래밍 기술을 지속적으로 적용한다.
- 개발된 소프트웨어의 품질이 유지되도록 지속적으로 검증한다.
- 소프트웨어 개발 관련 사항과 결과를 명확하게 기록한다.

### 요구사항

| 구분 | 설명 |
| --- | --- |
| 기능 요구사항 | 사용자가 시스템을 통해 제공받기 원하는 기능 또는 시스템이 반드시 수행해야 하는 기능 |
| 비기능 요구사항 | 품질이나 제약 사항과 관련된 요구사항. 장비 구성, 성능, 인터페이스, 테스트, 보안 등이 포함된다. |

### 요구사항 분석

- 소프트웨어가 무엇을 해야 하는지를 추적하여 요구사항 명세를 작성한다.
- 자료 흐름도(DFD, Data Flow Diagram)는 자료 흐름, 변환 과정, 기능을 도형 중심으로 표현한다.

#### DFD 구성 요소

| 구성 요소 | 설명 |
| --- | --- |
| Data Store | 자료 저장소. 파일이나 DB를 의미한다. |
| Data Flow | 자료의 흐름이나 연관 관계를 의미한다. |
| Process | 자료의 처리 과정을 의미한다. |
| Terminator | 시스템과 교신하는 외부 개체로, 입력 데이터를 만들고 출력 데이터를 받는다. |

#### 자료 사전 기호

| 기호 | 의미 | 설명 |
| --- | --- | --- |
| `=` | 자료의 정의 | `~로 구성되어 있다` |
| `+` | 자료의 연결 | 그리고(and) |
| `()` | 자료의 생략 | 생략 가능한 자료 |
| `[]` | 자료의 선택 | 또는(or) |
| `{}` | 자료의 반복 | 반복(iteration) |
| `**` | 자료의 설명 | 주석 |

### 시스템 개발 도구

#### HIPO

- HIPO(Hierarchy Input Process Output)는 시스템 분석 및 설계 단계에서 사용하는 문서화 기법이다.
- 시스템 기능을 계층적으로 나누고, 각 기능의 입력, 처리, 출력 과정을 차트로 표현한다.

#### UML

- 시스템 개발 과정에서 의사소통이 원활히 이루어지도록 표준화한 객체지향 모델링 언어이다.
- 구성 요소는 사물, 관계, 다이어그램이다.

##### UML 관계

| 종류 | 의미 | 예시 |
| --- | --- | --- |
| 연관 | 서로 관련되어 있음 | 사람 - 집 |
| 의존 | 한 사물의 명세가 바뀌면 다른 사물에 영향을 줌 | 등급 -> 할인율 |
| 일반화 | 상위 모듈은 더 일반적인 개념, 하위 모듈은 더 구체적인 개념을 가짐 | 아메리카노 -> 커피 |
| 실체화 | 한 객체가 다른 객체에게 오퍼레이션 수행을 지정 | 새 -> 날 수 있다 |
| 집합 | 전체와 부분이 독립적으로 포함 관계를 가짐 | 프린터 - 컴퓨터 |
| 포함 | 집합 관계의 특수 형태로, 포함하는 사물 변화가 포함되는 사물에 영향을 미침 | 열쇠 - 문 |

##### 구조적 다이어그램

| 구분 | 표현 |
| --- | --- |
| 클래스 다이어그램 | 클래스, 속성, 클래스 사이의 관계 |
| 객체 다이어그램 | 객체(인스턴스)와 객체 사이의 관계 |
| 컴포넌트 다이어그램 | 구현 모듈인 컴포넌트 간의 관계나 인터페이스 |
| 배치 다이어그램 | 결과물, 프로세스, 컴포넌트 등 물리적 요소의 위치 |
| 복합체 구조 다이어그램 | 클래스나 컴포넌트가 복합 구조를 갖는 경우의 내부 구조 |
| 패키지 다이어그램 | 유스케이스나 클래스 등 모델 요소를 그룹화한 패키지의 관계 |

##### 행위 다이어그램

| 구분 | 표현 |
| --- | --- |
| 유스케이스 다이어그램 | 시스템 기능을 사용자의 관점에서 표현한다. |
| 순차 다이어그램 | 객체들 사이의 메시지 교환을 시간 순서로 표현한다. |
| 커뮤니케이션 다이어그램 | 동작에 참여하는 객체들이 주고받는 메시지와 연관 관계를 표현한다. |
| 상태 다이어그램 | 하나의 객체가 가진 상태와 상태 변화를 표현한다. |
| 활동 다이어그램 | 객체의 처리 로직이나 조건에 따른 처리 흐름을 순서대로 표현한다. |
| 상호작용 개요 다이어그램 | 상호작용 다이어그램 간의 제어 흐름을 표현한다. |
| 타이밍 다이어그램 | 객체 상태 변화와 시간 제약을 표현한다. |

##### 유스케이스 다이어그램

- 시스템/시스템 범위: 유스케이스를 사각형으로 묶어 시스템 범위를 표현한다.
- 액터: 시스템과 상호작용하는 모든 외부 요소이다.
- 주 액터: 시스템을 사용함으로써 이득을 얻는 대상이다.
- 부 액터: 주 액터의 목적 달성을 위해 시스템에 서비스를 제공하는 외부 시스템이다.
- 유스케이스: 시스템이 액터에게 제공하는 서비스나 기능이다.

| 관계 | 의미 |
| --- | --- |
| 포함(`<<include>>`) | 공통 기능을 별도 유스케이스로 분리하여 재사용한다. |
| 확장(`<<extend>>`) | 기본 유스케이스 수행 중 특정 조건을 만족할 때 추가 기능을 수행한다. |
| 일반화 | 상위/하위 유스케이스 또는 액터 관계를 표현한다. |

##### 순차 다이어그램 구성 요소

- 생명선: 객체가 메모리에 존재하는 기간을 표현한다.
- 실행 상자(활성 상자): 객체가 메시지를 주고받으며 구동 중임을 표현한다.
- 메시지: 객체가 상호작용을 위해 주고받는 정보이다.
- 스테레오 타입: 기본 기능 외 추가 기능을 표현한다.

## 네트워크

### 기본 개념

#### 패킷 교환 방식

| 방식 | 설명 |
| --- | --- |
| 가상 회선 방식 | 연결형 통신 방식이다. 경로 설정 후 패킷을 순서대로 운반한다. |
| 데이터그램 방식 | 연결 경로를 설정하지 않고 패킷을 독립적으로 운반한다. 순서가 바뀔 수 있다. |

#### 프로토콜

데이터 교환을 표준화한 통신 규약이다.

| 기본 요소 | 설명 |
| --- | --- |
| 구문 | 데이터의 형식, 구조, 순서, 길이 등 |
| 의미 | 각 필드의 의미와 역할 |
| 시간 | 전송 타이밍, 순서, 속도 제어 |

### 네트워크 토폴로지

| 형태 | 설명 |
| --- | --- |
| 망형 | 모든 지점의 컴퓨터를 연결한 형태로, 노드 연결성이 높다. |
| 계층형/트리형 | 중앙 컴퓨터와 단말 장치를 계층적으로 연결한다. |
| 링형 | 이웃하는 컴퓨터와 단말 장치를 포인트 투 포인트 방식으로 연결한다. |
| 성형 | 중앙 집중식 네트워크 구성이다. |
| 버스형/선형 | 한 개의 통신 회선에 여러 단말 장치를 연결한다. |

### 네트워크 분류

| 분류 | 설명 |
| --- | --- |
| LAN | 가까운 거리에 있는 자원을 연결한다. 데이터 전송 속도가 빠르고 오류 발생률이 낮다. IEEE 802가 LAN 표준안이다. |
| WAN | 국가와 국가, 대륙과 대륙처럼 멀리 떨어진 사이트를 연결한다. |

### OSI 7계층

| 계층 | 핵심 역할 |
| --- | --- |
| 응용 계층 | 사용자 인터페이스 제공 |
| 표현 계층 | 시스템 간 포맷 호환, 인코딩/디코딩 |
| 세션 계층 | 세션 관리, 연결 유지 |
| 전송 계층 | 포트 번호 기반 종단 간 통신 |
| 네트워크 계층 | IP 주소 기반 라우팅 |
| 데이터 링크 계층 | MAC 주소 기반 프레임 전송 |
| 물리 계층 | 전기 신호, 광 신호, 라디오 신호 등 물리적 전송 |

전송 예시:

1. 응용 계층: HTTP 요청 작성
2. 표현 계층: 요청 내용을 UTF-8로 인코딩
3. 세션 계층: TCP 연결 설정
4. 전송 계층: TCP 세그먼트 생성, 포트 지정
5. 네트워크 계층: IP 주소로 패킷 라우팅
6. 데이터 링크 계층: MAC 주소로 프레임 구성
7. 물리 계층: 전기 신호로 전송

### 전송 계층

#### 프로토콜

| 프로토콜 | 설명 |
| --- | --- |
| TCP | 가상 회선 방식 기반의 신뢰성 있는 연결지향형 전달 서비스를 제공한다. |
| UDP | 비연결형 서비스를 제공한다. 오버헤드가 적고 전송 속도가 빠르다. |

#### 흐름 제어

- 네트워크 내 원활한 흐름을 위해 패킷의 양이나 속도를 규제한다.
- 정지-대기: 수신 측의 확인 신호(ACK)를 받은 뒤 다음 패킷을 전송한다.
- 슬라이딩 윈도우: ACK를 받지 않아도 미리 정해진 패킷 수만큼 연속 전송한다.

### 네트워크 계층

#### 프로토콜

| 프로토콜 | 설명 |
| --- | --- |
| IP | 데이터그램 기반의 비연결형 서비스 |
| ICMP | IP와 조합하여 통신 중 발생하는 제어 메시지, 오류 처리, 경로 변경을 관리 |
| ARP | IP 주소를 MAC Address로 변환 |
| RARP | MAC Address를 IP 주소로 변환 |
| IPsec | IP 패킷 단위의 데이터 변조 방지 및 은닉 기능을 제공 |

#### 라우팅

- 라우터는 서로 다른 네트워크 대역의 호스트를 연결하고 최적 경로를 선택한다.
- 라우팅은 최적 패킷 교환 경로를 결정하는 기능이다.

| 구분 | 설명 |
| --- | --- |
| IGP | 하나의 자율 시스템 내부 라우팅에 사용한다. |
| RIP | 거리 벡터 라우팅 프로토콜이며 벨만-포드 알고리즘을 사용한다. 소규모 동종 네트워크에 적합하다. |
| OSPF | 다익스트라 알고리즘을 사용하며 대규모 네트워크에서 많이 사용한다. |
| EGP/BGP | 자율 시스템 간 라우팅에 사용한다. BGP는 EGP의 단점을 보완한다. |

#### NAT

- NAT(Network Address Translation)는 하나의 정식 IP 주소에 여러 가상 사설 IP 주소를 할당 및 연결한다.
- IP 마스커레이드를 이용하면 여러 내부 노드가 하나의 외부 IP로 접속할 수 있다.

### 데이터 링크 계층

| 프로토콜 | 설명 |
| --- | --- |
| L2TP | PPTP와 L2F의 장점을 결합한 터널링 프로토콜이다. 암호화/인증 기능은 별도 보안 프로토콜과 함께 사용하는 경우가 많다. |
| PPTP | PPP 패킷을 IP 패킷에 캡슐화하여 통과시키기 위한 프로토콜이다. |
| L2F | 인터넷을 통한 VPN 연결을 위해 개발된 터널링 프로토콜이다. |

### IP

인터넷에 연결된 모든 컴퓨터 자원을 구분하기 위한 고유 주소이다.

#### IPv4

- 8비트씩 4부분, 총 32비트로 구성된다.
- IP 주소는 네트워크 ID와 호스트 ID로 구성된다.
- 서브넷 마스크는 IP 주소를 네트워크 주소와 호스트 주소로 분리한다.
- CIDR 표기법 예시: `192.168.10.100/24`

| 클래스 | 대역 | 시작 비트 |
| --- | --- | --- |
| A | `1.0.0.0 ~ 127.255.255.255` | `0` |
| B | `128.0.0.0 ~ 191.255.255.255` | `10` |
| C | `192.0.0.0 ~ 223.255.255.255` | `110` |

#### IPv6

- 16비트씩 8부분, 총 128비트로 구성된다.
- 각 부분을 16진수로 표현하고 콜론(`:`)으로 구분한다.

| 주소 체계 | 설명 |
| --- | --- |
| 유니캐스트 | 단일 송신자 - 단일 수신자 |
| 멀티캐스트 | 단일 송신자 - 다중 수신자 |
| 애니캐스트 | 단일 송신자 - 가장 가까운 단일 수신자 |

### 서브네팅

- IP 주소에서 호스트 ID 일부 비트를 추가 네트워크 ID로 재할당하여 하나의 네트워크 주소 블록을 더 작은 서브네트워크로 분할한다.
- FLSM(Fixed Length Subnet Mask): 고정된 크기로 주소를 할당한다.
- IP Subnet-Zero: 첫 번째 서브넷 사용을 허용한다.

### 도메인

- 도메인 네임은 숫자로 된 IP 주소를 사람이 이해하기 쉬운 문자 형태로 표현한 것이다.
- DNS는 문자 도메인 네임을 컴퓨터가 이해할 수 있는 IP 주소로 변환한다.

### 네트워크 관련 신기술

| 기술 | 설명 |
| --- | --- |
| 메시 네트워크 | 대규모 디바이스 네트워크 생성에 최적화된 특수 목적 네트워크 기술 |
| 피코넷 | 여러 통신 장치가 블루투스나 UWB를 사용해 통신망을 형성 |
| 애드 혹 네트워크 | 모바일 호스트만으로 구성한 네트워크. 별도 유선망 구축이 어렵거나 단기간 사용 시 적합 |
| 파장 분할 다중화 | 서로 다른 파장의 복수 신호를 보내 여러 단말기가 동시에 통신 회선을 사용 |
| SDDC | 소프트웨어 조작만으로 관리 및 제어되는 데이터 센터 |
| LOD | 누구나 사용할 수 있도록 웹에 공개된 연계 데이터 |
| SDN | 소프트웨어로 네트워킹을 가상화하여 제어하고 관리하는 네트워크 |
| USN | 센서로 수집한 정보를 무선으로 수집할 수 있도록 구성한 네트워크 |
| SSO | 한 번의 로그인으로 여러 사이트를 이용할 수 있게 하는 시스템 |

## 운영체제

### UNIX

- 시분할 시스템을 위해 설계된 대화식 운영체제이다.
- 커널과 쉘로 구성된다.
- 쉘은 명령어 해석기 역할을 한다.

### Secure OS

보안 기능을 갖춘 커널을 이식하여 외부 침입으로부터 시스템 자원을 보호하는 운영체제이다.

### 가상 기억장치

| 기법 | 설명 |
| --- | --- |
| 페이징 | 동일한 크기의 페이지 단위로 관리한다. |
| 세그먼테이션 | 논리 단위인 세그먼트로 관리한다. |

#### 페이지 교체 알고리즘

- LRU(Least Recently Used): 가장 오랫동안 사용하지 않은 페이지를 교체한다.
- LFU(Least Frequently Used): 사용 빈도가 가장 낮은 페이지를 교체한다.

### 프로세스 상태 전이

일반적인 흐름은 `제출 -> 접수 -> 준비 -> 실행 -> 종료`이다. 입출력 발생 시 대기 상태로 전이되고, 입출력 종료 후 준비 상태로 돌아간다.

### 스케줄링

시스템의 여러 자원을 프로세스에게 할당하는 작업이다.

| 방식 | 설명 |
| --- | --- |
| FCFS | 먼저 도착한 프로세스를 먼저 처리한다. |
| SJF | 실행 시간이 가장 짧은 프로세스부터 처리한다. |
| HRN | 우선순위 = `(대기시간 + 서비스 시간) / 서비스 시간` |
| RR | 일정 시간만 실행하고 다음 프로세스로 넘긴다. |
| SRT | 현재 프로세스의 남은 시간과 새 프로세스의 실행 시간을 비교한다. |

## 데이터베이스

### DBMS

사용자 요구에 따라 정보를 생성하고 데이터베이스를 관리하는 소프트웨어이다.

| 필수 기능 | 설명 |
| --- | --- |
| 정의(DDL) | 데이터 구조를 정의한다. |
| 조작(DML) | 데이터를 검색, 삽입, 삭제, 갱신한다. |
| 제어(DCL) | 권한, 무결성, 병행 수행 등을 제어한다. |

### 스키마

데이터베이스의 구조와 제약 조건에 관한 전반적인 명세이다.

| 구분 | 설명 |
| --- | --- |
| 외부 스키마 | 사용자가 필요로 하는 DB의 논리적 구조 |
| 개념 스키마 | 데이터베이스 전체의 논리적 구조. 개체, 관계, 제약조건, 접근 권한, 보안 정책 등을 포함 |
| 내부 스키마 | 물리적 저장장치 입장에서 본 데이터베이스 구조. 레코드 형식, 인덱스 유무 등을 포함 |

### DB 설계 순서

1. 요구 조건 분석
2. 개념적 설계: 현실 세계 인식을 추상적 개념으로 표현한다. 개념 스키마 모델링, 트랜잭션 모델링, ERD 작성이 포함된다.
3. 논리적 설계: 특정 DBMS가 지원하는 논리적 자료 구조로 변환한다. 트랜잭션 인터페이스 설계와 정규화를 수행한다.
4. 물리적 설계: 물리적 구조의 데이터로 변환한다. 파일 저장 구조와 액세스 경로를 결정한다.
5. 구현: 테이블 정의서와 명세서 등을 산출한다.

### 개념적 모델

- 현실 세계의 모델을 추상화하여 체계적으로 표현한 모형이다.
- 요소: 구조, 연산, 제약조건

### ERD

| 기호 | 기호 이름 | 의미 |
| --- | --- | --- |
| 사각형 | 개체(Entity) 타입 | 개체를 표현한다. |
| 마름모 | 관계(Relationship) 타입 | 개체 간 관계를 표현한다. |
| 타원 | 속성(Attribute) | 속성을 표현한다. |
| 이중 타원 | 다중값 속성 | 여러 값을 가질 수 있는 속성 |
| 밑줄 타원 | 기본키 속성 | 기본키를 표현한다. |
| 복수 타원 | 복합 속성 | 예: 성명은 성과 이름으로 구성 |
| 선 위의 `1:1`, `1:N`, `N:M` | 대응 수 | 개체 간 관계의 대응 수를 표현한다. |

### 릴레이션

| 용어 | 설명 |
| --- | --- |
| 릴레이션 | 데이터를 표 형태로 표현한 것 |
| 릴레이션 스키마 | 릴레이션의 구조 |
| 릴레이션 인스턴스 | 실제 값 |
| 튜플 | 릴레이션을 구성하는 각각의 행. 레코드 |
| 카디널리티 | 튜플의 수 |
| 속성 | 데이터베이스를 구성하는 가장 작은 논리적 단위. 데이터 필드 |
| 디그리 | 속성의 수 |
| 도메인 | 하나의 속성이 취할 수 있는 같은 타입의 원자값 집합 |

#### 키

| 키 | 설명 |
| --- | --- |
| 후보키 | 튜플을 유일하게 식별하기 위해 사용하는 속성들의 부분 집합. 유일성과 최소성을 만족한다. |
| 기본키 | 후보키 중에서 선정된 주 키. 중복값과 `NULL`을 허용하지 않는다. |
| 대체키 | 기본키를 제외한 나머지 후보키 |
| 슈퍼키 | 유일성은 만족하지만 최소성은 만족하지 않을 수 있는 속성 집합 |
| 외래키 | 다른 릴레이션의 기본키를 참조하는 속성 또는 속성 집합 |

#### 무결성

- 무결성은 데이터베이스에 저장된 데이터 값과 현실 세계의 실제 값이 일치하는 정확성이다.
- 개체 무결성: 기본키를 구성하는 속성은 `NULL`과 중복값을 가질 수 없다.
- 참조 무결성: 외래키 값은 `NULL`이거나 참조 릴레이션의 기본키 값과 동일해야 한다.

### 관계 대수

주어진 릴레이션 조작을 위한 연산의 집합이다.

| 종류 | 연산 | 설명 |
| --- | --- | --- |
| 일반 집합 연산자 | 합집합(UNION) | 결과에서 중복 튜플을 제거한다. |
| 일반 집합 연산자 | 교집합(INTERSECTION) | 공통 튜플을 구한다. |
| 일반 집합 연산자 | 차집합(DIFFERENCE) | 한 릴레이션에는 있고 다른 릴레이션에는 없는 튜플을 구한다. |
| 일반 집합 연산자 | 교차곱(CARTESIAN PRODUCT) | 두 릴레이션 튜플의 순서쌍을 구한다. |
| 순수 관계 연산자 | SELECT | 조건을 만족하는 튜플의 부분 집합을 구한다. |
| 순수 관계 연산자 | PROJECT | 제시된 속성값만 추출하여 새 릴레이션을 만든다. |
| 순수 관계 연산자 | JOIN | 공통 속성을 중심으로 두 릴레이션을 합친다. |
| 순수 관계 연산자 | DIVISION | 특정 속성을 제외한 관련 튜플을 구한다. |

관계 해석은 원하는 정보가 무엇인지 정의하는 비절차적 특성을 가진다.

### 이상

데이터가 불필요하게 중복되어 릴레이션 조작 시 예기치 않게 발생하는 곤란한 상황이다.

| 이상 | 설명 |
| --- | --- |
| 삽입 이상 | 필요한 데이터가 없으면 삽입할 수 없는 현상 |
| 삭제 이상 | 의도와 상관없는 값들이 함께 삭제되는 현상 |
| 갱신 이상 | 일부 튜플만 갱신되어 정보 불일치가 발생하는 현상 |

### 함수적 종속

- 함수적 종속 `X -> Y`: 속성 `X`의 값이 주어지면 속성 `Y`의 값이 항상 유일하게 결정되는 관계이다.
- 완전 함수적 종속: `X -> Y`이고, `X`의 부분집합만으로는 `Y`를 결정할 수 없다.
- 부분 함수적 종속: `X -> Y`이면서 `X`의 일부 속성만으로도 `Y`를 결정할 수 있다.
- 이행적 함수적 종속: `X -> Y`이고 `Y -> Z`일 때 `X -> Z`가 성립한다.

### 정규화

테이블의 속성들이 상호 종속적인 관계를 갖는 특성을 이용하여 테이블을 무손실 분해하는 과정이다. 중복을 제거하여 이상 발생 가능성을 줄인다.

| 정규형 | 조건 |
| --- | --- |
| 제1정규형(1NF) | 도메인이 원자값 |
| 제2정규형(2NF) | 부분 함수 종속 제거 |
| 제3정규형(3NF) | 이행적 함수 종속 제거 |
| BCNF | 결정자이면서 후보키가 아닌 것을 제거 |
| 제4정규형(4NF) | 다치 종속 제거 |
| 제5정규형(5NF) | 조인 종속성 이용 |

- 다치 종속: `(A, C) -> B`일 때 `A -> B`이지만 `C -> B`가 아닌 상태이다.
- 조인 종속: 테이블 속성의 부분 집합을 조인했을 때 원래 릴레이션과 동일하게 복원되는 상태이다.
- 반정규화: 성능 향상 등을 위해 정규화를 의도적으로 위배하는 것이다.

#### 반정규화 예시

- 중복 테이블 추가
- 집계 테이블 추가
- 진행 테이블 추가
- 특정 부분만 포함하는 테이블 추가

### 시스템 카탈로그

다양한 객체에 관한 정보, 즉 메타데이터를 포함하는 시스템 데이터베이스이다.

### 인덱스

데이터를 빠르게 조회하기 위해 `<키 값, 포인터>` 쌍으로 구성하는 데이터 구조이다.

### 트랜잭션

하나의 논리적 기능을 수행하기 위한 작업 단위이다.

| 특성 | 설명 |
| --- | --- |
| Atomicity(원자성) | 트랜잭션은 모두 반영되거나 모두 취소되어야 한다. |
| Consistency(일관성) | 트랜잭션 전후로 일관성 있는 데이터베이스 상태를 유지한다. |
| Isolation(독립성) | 병행 실행 시 다른 트랜잭션에 영향을 주지 않아야 한다. |
| Durability(영속성) | 완료된 결과는 데이터베이스에 영구적으로 반영되어야 한다. |

#### CRUD 분석

프로세스와 테이블 간 CRUD 매트릭스를 만들어 트랜잭션을 분석한다.

#### 병행 제어

- 동시에 실행되는 트랜잭션 간 상호작용을 제어한다.
- 로킹: 접근한 데이터에 대한 연산을 마칠 때까지 추가 접근을 제한한다.
- 로킹 단위: 한꺼번에 로킹할 수 있는 객체의 크기이다.
- 타임스탬프 순서: 트랜잭션 간 처리 순서를 미리 결정한다.

#### 교착 상태

서로 다른 프로세스가 점유 중인 자원을 요구하며 무한정 기다리는 현상이다.

| 발생 조건 | 설명 |
| --- | --- |
| 상호 배제 | 한 번에 한 프로세스만 공유 자원을 사용할 수 있다. |
| 점유 대기 | 자원을 점유한 채 다른 자원을 기다리는 프로세스가 있다. |
| 비선점 | 다른 프로세스에 할당된 자원을 강제로 빼앗을 수 없다. |
| 환형 대기 | 자원과 대기 프로세스가 원형으로 구성된다. |

| 해결 방법 | 설명 |
| --- | --- |
| 예방 | 교착 상태 발생 조건을 제거한다. |
| 회피 | 교착 상태가 발생하지 않도록 적절히 피해 간다. 은행원 알고리즘이 대표적이다. |
| 검출 | 교착 상태 발생 여부를 점검하여 발견한다. |
| 회복 | 프로세스를 종료하거나 자원을 선점하여 회복한다. |

### 회복

데이터베이스가 손상되었을 때 손상 이전의 정상 상태로 복구하는 작업이다.

| 기법 | 설명 |
| --- | --- |
| REDO | 로그를 이용하여 데이터 변경을 재적용한다. |
| UNDO | 로그를 이용하여 데이터 변경을 취소한다. |
| 즉각 갱신 | 트랜잭션이 데이터를 갱신하면 부분 완료 전이라도 즉시 실제 DB에 반영한다. |

## 하드웨어

### RAID

2개 이상의 하드 디스크로 디스크 배열을 구성하고, 데이터를 서로 다른 디스크에 분산 저장하거나 다중화하는 기술이다.

| RAID | 설명 |
| --- | --- |
| RAID 0 | 스트라이핑. 디스크를 병렬로 연결하여 용량과 속도가 증가하지만, 하나의 디스크만 손상되어도 전체 데이터가 손상된다. |
| RAID 1 | 미러링. 같은 데이터를 다른 디스크에 동일하게 복사한다. |
| RAID 2~4 | 오류 정정 부호를 비트/바이트/워드 단위로 저장하고 나머지 디스크는 RAID 0처럼 활용한다. 최소 3개 디스크가 필요하다. |
| RAID 5 | 오류 정정 부호를 블록 단위로 여러 디스크에 분산 저장한다. 최소 3개 디스크가 필요하다. |
| RAID 6 | RAID 5와 유사하지만 오류 정정 부호를 2개 저장한다. 최소 4개 디스크가 필요하다. |

## 프로그래밍

### SQL

#### DDL

```sql
DROP TABLE 직원;

CREATE TABLE 직원 (
  사번 CHAR(15),
  이름 CHAR(4) NOT NULL,
  전화번호 CHAR(20),
  부서번호 CHAR(10),
  경력 INT,
  기본급 INT,
  CONSTRAINT 최소기본급 CHECK (기본급 >= 10000000),
  PRIMARY KEY (사번),
  UNIQUE (전화번호),
  FOREIGN KEY (부서번호) REFERENCES 부서(부서번호)
    ON DELETE NO ACTION
    ON UPDATE CASCADE
);

CREATE VIEW 3학년학생 AS
SELECT *
FROM 학생
WHERE 학년 = 3
WITH CHECK OPTION;
```

#### DML

```sql
SELECT 이름
FROM 자격증
GROUP BY 이름
HAVING COUNT(*) >= 2;

INSERT INTO 테이블명 VALUES (...);

DELETE FROM 테이블명
WHERE 조건;

UPDATE 테이블명

WHERE 조건;
```

#### DCL

```sql
GRANT ALL ON 학생 TO 홍길동 WITH GRANT OPTION;

REVOKE SELECT ON 수강 FROM 박문수 CASCADE;

REVOKE GRANT OPTION FOR SELECT ON 수강 FROM 박문수;
```

SELECT

| SSL | TCP/IP 계층과 애플리케이션 계층 사이에서 인증, 암호화, 무결성을 제공하는 프로토콜이다. |
| S-HTTP | 클라이언트와 서버 간 전송 메시지를 암호화하는 프로토콜이다. |

### EAI

EAI(Enterprise Application Integration)는 애플리케이션 간 상호 연동을 가능하게 해주는 서비스이다.

| 방식 | 설명 |
| --- | --- |
| Point-to-Point | 1:1 방식으로 연결한다. |
| Hub & Spoke | 허브를 통해 데이터를 전송하는 중앙 집중형 방식이다. |
| Message Bus | 미들웨어를 이용해 연결한다. |
| Bus Hybrid | 그룹 내는 Hub & Spoke, 그룹 간은 Message Bus를 사용한다. |

### UI 기본 원칙

### 테스트 원리

- 파레토 법칙: 20%의 모듈에서 결함의 80%가 발견된다.
- 살충제 패러독스: 동일한 테스트 케이스를 반복하면 더 이상 결함이 발견되지 않는다.
- 오류-부재의 궤변: 결함이 없어도 요구사항을 만족하지 못하면 품질이 높다고 볼 수 없다.

### 테스트 구분

| 구분 | 설명 |
| --- | --- |
| 정적 테스트 | 프로그램을 실행하지 않고 명세서나 코드를 대상으로 검사한다. |
| 동적 테스트 | 프로그램을 실행하여 오류를 찾는다. |
| 화이트박스 테스트 | 원시 코드의 모든 논리 경로를 테스트한다. 기초 경로 검사, 제어 구조 검사가 있다. |
| 블랙박스 테스트 | 기능 작동을 입증한다. 동치 분할 검사, 경계값 분석, 원인-효과 그래프 검사가 있다. |

화이트박스 테스트의 결정 검증 기준은 모든 조건식 결과가 `true`와 `false`를 모두 갖도록 테스트하는 기준이다.

### 테스트 유형

- 인수 테스트: 요구사항 충족 여부를 검사한다.
- 알파 테스트: 개발자 앞에서 통제된 환경에서 수행한다.
- 베타 테스트: 사용자가 직접 수행한다.
- 하향식 통합 테스트: 상위 모듈에서 하위 모듈 방향으로 통합하며 테스트한다. Stub을 활용한다.
- 상향식 통합 테스트: 테스트 드라이버를 활용하여 입출력을 확인한다.
- 회귀 테스트: 변경된 모듈이나 컴포넌트에 새로운 오류가 있는지 확인한다.
- 테스트 오라클: 사전에 정의된 참값을 대입하여 비교한다.

### 암호 알고리즘

| 구분 | 설명 | 예시 |
| --- | --- | --- |
| 개인키 암호화(대칭키) | 동일한 키로 암호화와 복호화를 수행한다. | IDEA, Skipjack, DES, AES, ARIA, SEED |
| 공개키 암호화(비대칭키) | 공개키로 암호화하고 비밀키로 복호화한다. | RSA, ECC |
| 해시 | 임의 입력 데이터를 고정 길이 해시값으로 변환한다. | SHA, MD5 |

- Salt: 동일한 패스워드가 서로 다른 암호값으로 저장되도록 추가하는 값이다.
- TKIP: 무선 LAN 보안에 사용된 WEP 방식을 보완한 데이터 보안 프로토콜이다.
- 템퍼 프루핑: 소프트웨어 위변조가 발생할 경우 오작동을 일으켜 악용을 방지한다.

### 공격 유형

#### 서비스 거부 공격

대량의 데이터를 특정 서버에 집중 전송하여 정상 기능을 방해한다.

| 공격 | 설명 |
| --- | --- |
| Ping of Death | 매우 큰 패킷을 전송하여 네트워크를 마비시킨다. |
| SMURFING | IP 또는 ICMP 특성을 악용하여 특정 사이트에 데이터를 집중 전송한다. |
| Land Attack | 송신 IP와 수신 IP를 모두 공격 대상 IP로 설정해 전송한다. |
| SYN Flooding | 가상의 클라이언트로 위장하여 서버를 대기 상태로 만든다. |
