2023년 3월 11일 리눅스마스터 1급 1차 기출에서 반복해서 확인해야 할 개념과 명령을 과목별로 정리한다.

> 명령과 설정은 문제에 나온 CentOS 7 및 전통적인 SysV·BIND·Sendmail 환경을 기준으로 한다. 최신 배포판에서는 명령이나 기본 프로그램이 달라질 수 있다.

## 1과목: 리눅스 실무의 이해

### 리눅스와 유닉스

- 리눅스 커널은 1991년 리누스 토르발스가 처음 공개했다.
- 교육용 유닉스 계열 운영체제 MINIX는 앤드루 타넨바움이 만들었다.
- 리눅스는 커널이고, GNU 도구와 각종 프로그램을 결합한 완성된 운영체제를 리눅스 배포판이라고 한다.

리눅스의 대표적인 특징은 다음과 같다.

- 다중 사용자와 다중 작업 지원
- 소스 코드가 공개된 자유 소프트웨어 생태계
- 여러 명령을 연결하는 파이프와 입출력 리다이렉션
- 여러 터미널을 전환해 사용하는 가상 콘솔
- 다양한 CPU와 하드웨어 플랫폼 지원
- TCP/IP를 비롯한 강력한 네트워크 기능

```bash
# 표준 출력을 파일로 덮어쓴다.
command > output.txt

# 표준 출력을 파일 끝에 추가한다.
command >> output.txt

# 앞 명령의 표준 출력을 다음 명령의 표준 입력으로 전달한다.
ps aux | grep httpd
```

### RAID

| 레벨 | 방식 | 최소 디스크 | 특징 |
|---|---|---:|---|
| RAID 0 | 스트라이핑 | 2 | 빠르고 전체 용량 사용, 장애 허용 없음 |
| RAID 1 | 미러링 | 2 | 같은 데이터를 복제, 가용 용량은 절반 |
| RAID 4 | 전용 패리티 | 3 | 블록 단위 스트라이핑, 패리티 디스크 병목 |
| RAID 5 | 분산 패리티 | 3 | 디스크 1개 장애 허용 |
| RAID 6 | 이중 분산 패리티 | 4 | 디스크 2개 장애 허용 |
| RAID 0+1 | 미러링한 스트라이프 | 4 | RAID 0을 RAID 1로 복제 |
| RAID 1+0 | 스트라이핑한 미러 | 4 | RAID 1 묶음을 RAID 0으로 결합, 일반적으로 장애 대응이 유리 |

소프트웨어 RAID 1을 디스크 두 개로 만드는 예다.

```bash
mdadm -C /dev/md2 -l 1 -n 2 /dev/sdb1 /dev/sdc1
cat /proc/mdstat
```

- MBR 파티션의 Linux RAID autodetect 코드는 `fd`이다.
- `82`는 swap, `83`은 일반 Linux 파일시스템, `8e`는 Linux LVM이다.
- 생성된 소프트웨어 RAID의 상태는 `/proc/mdstat`에서 확인한다.

### 부팅과 systemd

GRUB에서 root 암호를 복구하기 위해 커널 인자를 바꾸는 전통적인 방식은 다음과 같다.

```text
rw init=/bin/sh
```

- `rw`: 루트 파일시스템을 읽기·쓰기 상태로 사용
- `init=/bin/sh`: 정상 init 대신 셸 실행

systemd 서비스 관리의 핵심 명령은 다음과 같다.

```bash
systemctl start sshd       # 지금 시작
systemctl stop sshd        # 지금 중지
systemctl restart sshd     # 재시작
systemctl status sshd      # 상태 확인
systemctl enable sshd      # 부팅 시 자동 시작
systemctl disable sshd     # 자동 시작 해제
systemctl enable --now sshd
```

### 셸, 프로세스와 작업 제어

프로세스 생성, 시그널, `nice`, `renice`, `jobs`, `fg`, `bg`의 자세한 내용은 [리눅스마스터 1급: 프로세스 관리]({{< relref "posts/project/리눅스마스터-1급/리눅스마스터-1급-프로세스-관리.md" >}})를 참고한다.

기출에서 특히 주의할 내용은 다음과 같다.

- 사용자가 조정하는 값은 `NI`이고 범위는 `-20`부터 `19`까지다.
- NI가 작을수록 CPU 우선순위가 높고, 클수록 우선순위가 낮다.
- 새 프로세스는 `nice`, 실행 중인 PID는 `renice`로 조정한다.
- `fg`와 `bg`에는 PID가 아니라 작업번호를 사용한다.

```bash
fg %3
bg %3
renice 5 513       # PID 513의 NI를 5로 바꿔 우선순위를 낮춘다.
```

> 35번은 “우선순위를 낮춘다”면서 `renice -5 513`만 제시해 문구와 선택지가 모순된다. `0`에서 `-5`로 바꾸면 실제 CPU 우선순위는 높아진다. 출제 의도상 답은 실행 중인 PID를 받는 `renice -5 513`이다.

### 셸 명령 치환과 종료 상태

```bash
echo "My Home is $(pwd)"
test 20 -gt 30
echo $?
```

- `$(pwd)` 또는 `` `pwd` ``는 명령 실행 결과로 치환된다.
- `$?`에는 직전 명령의 종료 상태가 저장된다.
- 참·성공은 `0`, 거짓·실패는 보통 `1` 이상의 값이다.
- 따라서 `20 -gt 30`의 결과는 거짓이고 `$?`는 `1`이다.

### cron

cron 필드 순서는 `분 시 일 월 요일`이다.

```text
# 매주 수요일(3), 금요일(5) 오전 1시 2분
2 1 * * 3,5 /etc/check.sh
```

쉼표는 각각의 값을, 하이픈은 연속 범위를 뜻한다. `3,5`는 수요일과 금요일이고 `3-5`는 수요일부터 금요일까지다.

#### 서브넷 계산

IPv4 네트워크 주소는 IP와 서브넷 마스크를 비트 AND하여 구한다. 브로드캐스트 주소는 호스트 부분을 모두 1로 만든 값이다. 일반적인 서브넷에서는 네트워크 주소와 브로드캐스트 주소를 호스트에 할당하지 않는다.

예를 들어 `192.168.5.13/24`라면 다음과 같다.

```text
네트워크 주소:     192.168.5.0
사용 가능한 범위:  192.168.5.1 ~ 192.168.5.254
브로드캐스트 주소: 192.168.5.255
```

#### IP와 연결 정보 확인

```bash
ip address              # 인터페이스와 로컬 IP
ip route                # 라우팅과 기본 게이트웨이
hostname -I             # 호스트에 설정된 IP를 간단히 출력
ss -tn                  # TCP 연결과 상대 IP
ip neigh                # 이웃 IP와 MAC 주소
arp -a                   # 전통적인 ARP 캐시 확인
ethtool eth0             # 링크 속도와 NIC 상태
```

SSH 접속 상대 주소는 `ss -tn`, `$SSH_CLIENT`, `$SSH_CONNECTION` 등으로 확인할 수 있다.

## 2과목: 리눅스 시스템 관리

### 사용자·그룹 설정 파일

#### `/etc/passwd`

```text
사용자명:암호표시:UID:GID:설명:홈 디렉터리:로그인 셸
```

홈 디렉터리는 6번째 필드다.

#### `/etc/group`

```text
그룹명:암호표시:GID:보조 그룹 구성원
```

구성원 목록은 4번째 필드다. 엄밀한 그룹 관리자 정보는 `/etc/gshadow`의 3번째 필드에 기록된다.

#### 계정 잠금과 암호 정보

```bash
usermod -L ihduser      # 잠금
usermod -U ihduser      # 잠금 해제
passwd -l ihduser       # 암호 잠금
chage -l ihduser        # 암호·계정 만료 정보 확인
```

`passwd -d`는 암호 삭제이고, `usermod -l`은 로그인 이름 변경이므로 잠금과 구분한다.

### 로그인 사용자 확인

```bash
w             # uptime, load average, 사용자별 작업까지 표시
who           # 로그인 사용자 정보
users         # 로그인 사용자 이름
lslogins      # 시스템 계정 정보
```

### 특수 권한과 파일 속성

```text
-rwsr-xr-x root root /usr/bin/passwd
   ↑
 SetUID
```

SetUID가 설정된 실행 파일은 실행하는 동안 파일 소유자의 유효 권한으로 동작한다. `/usr/bin/passwd`를 일반 사용자가 실행해도 `/etc/shadow`를 갱신할 수 있는 이유다.

파일을 수정·삭제하지 못하게 하고 내용 추가만 허용하려면 append-only 속성을 사용한다.

```bash
chattr +a /etc/services
lsattr /etc/services
chattr -a /etc/services
```

`chattr +i`는 추가까지 포함한 모든 변경을 막는다. `setfacl`은 사용자와 그룹별 ACL을 관리하는 별개의 명령이다.

### 링크, 검색과 파일 시간

```bash
# /var/www/html이 /usr/local/apache/htdocs를 가리키게 한다.
ln -s /usr/local/apache/htdocs /var/www/html
```

`ln -s 대상 링크이름` 순서를 기억한다.

```bash
touch file       # 없으면 크기 0인 파일 생성, 있으면 atime·mtime 갱신
locate passwd    # updatedb가 만든 DB에서 빠르게 검색
updatedb         # locate DB 갱신
find / -user kim -perm 755
```

- `atime`: 마지막 접근 시간
- `mtime`: 파일 내용 수정 시간
- `ctime`: inode 메타데이터 변경 시간이며 `touch`로 임의의 값에 직접 맞출 수 없다.
- 새 파일은 `updatedb` 전까지 `locate`에서 검색되지 않을 수 있다.
- 사용자, 권한, 크기 같은 복합 조건 검색은 `find`가 담당한다.

### 패키지 관리

```bash
rpm -qa               # 설치된 모든 RPM 패키지
rpm -qc httpd         # httpd 패키지의 설정 파일
rpm -ql httpd         # httpd가 설치한 모든 파일
rpm -qf /path/file    # 파일을 설치한 패키지
yum info telnet-server
```

> 37번 선택지의 `-qC`가 대문자라면 표기 오류다. 설정 파일 조회의 실제 옵션은 소문자 `-qc`다.

### 커널 컴파일과 모듈

대표적인 커널 컴파일 순서는 다음과 같다.

```bash
make mrproper     # 이전 빌드 결과와 .config까지 정리
make menuconfig   # 터미널 메뉴에서 설정
make bzImage      # 압축 커널 이미지 빌드
```

X Window가 없다면 `make config`와 `make menuconfig`를 사용할 수 있다. `make xconfig`와 `make gconfig`는 그래픽 환경이 필요하다.

```bash
modprobe iptable_filter       # 의존성을 처리해 모듈 적재
```

### 백업과 복원

```bash
tar cvf text.tar *.c                    # 새 tar 생성
tar xvf text.tar                        # 해제
tar tvf text.tar                        # 목록 확인
tar -g snapshot -cvfp home1.tar /home   # listed incremental 증분 백업
```

tar 옵션의 핵심은 `c` 생성, `x` 해제, `t` 목록, `v` 상세 표시, `f` 파일명, `z` gzip이다. `-g`는 상태 목록을 이용한 증분 백업 옵션이다.

`dump`로 만든 백업은 `restore`로 복원한다.

```bash
restore -if backup.data
```

전통적인 `dump`는 XFS용 도구가 아니다. XFS에서는 `xfsdump`와 `xfsrestore`를 사용한다. `dd`, `cpio`, `rsync`는 XFS에서도 사용할 수 있다.

### 로그

syslog 심각도는 다음 순서다. 숫자가 작을수록 더 심각하다.

```text
0 emerg → 1 alert → 2 crit → 3 err → 4 warning → 5 notice → 6 info → 7 debug
```

```text
*.warn;kern.none
```

위 설정은 모든 facility의 warning 이상 로그를 선택하되 커널 로그는 제외한다. `=warn`은 warning만 정확히 선택하므로 의미가 다르다.

| 파일 | 내용 | 확인 명령 |
|---|---|---|
| `/var/log/secure` | 인증·보안 로그, 텍스트 | `cat`, `less` |
| `/var/log/wtmp` | 로그인·로그아웃 기록, 바이너리 | `last` |
| `/var/log/btmp` | 실패한 로그인 기록, 바이너리 | `lastb` |
| `/var/log/lastlog` | 사용자별 마지막 로그인, 바이너리 | `lastlog` |

명령행에서 로그 시스템에 메시지를 보낼 때는 `logger`를 사용한다.

```bash
logger -t myapp -p user.warning 'warning message'
```

## 3과목: 네트워크 및 서비스의 활용

### Apache와 Nginx

Nginx는 비동기 이벤트 기반 웹 서버이며 리버스 프록시, 로드 밸런싱, HTTP 캐시에 널리 사용한다.

Apache의 주요 설정은 다음과 같다.

```apache
DocumentRoot "/usr/local/apache/htdocs"
LoadModule userdir_module modules/mod_userdir.so
```

- `ServerRoot`: Apache 설정·실행 파일의 기준 경로
- `mod_userdir`: `http://server/~user/` 형태의 개인 홈페이지 기능


### DNS와 BIND

BIND는 ISC가 개발·배포하는 대표적인 DNS 서버이며 서버 데몬 이름은 `named`다.

`named.conf`에서는 다음 세 종류의 주석을 사용할 수 있다.

```text
/* C style */
// C++ style
# shell style
```

세미콜론은 주석이 아니라 문장의 끝을 표시한다.

DNS 질의를 다른 서버에만 전달하는 설정은 다음과 같다.

```text
forward only;
forwarders {
    168.126.63.1;
};
```

주요 레코드는 다음과 같다.

| 레코드 | 역할 |
|---|---|
| `A` | 호스트 이름을 IPv4 주소에 연결 |
| `AAAA` | 호스트 이름을 IPv6 주소에 연결 |
| `PTR` | 역방향 존에서 IP 주소를 호스트 이름에 연결 |
| `CNAME` | 별칭을 실제 호스트 이름에 연결 |
| `MX` | 도메인의 메일 서버와 우선순위 지정 |
| `NS` | 존의 권한 있는 네임서버 지정 |

정상적인 MX 설정 예시는 다음과 같다.

```text
@       IN MX 10 mail.ihd.or.kr.
mail    IN A     192.168.5.13
```

MX 레코드에는 우선순위가 필요하고, 완전한 도메인 이름은 마지막에 점을 붙인다.

> 85번 선택지는 정상적인 존 파일 표현과 다소 어긋난다. 우선순위와 마지막 점을 모두 포함한다는 기준의 출제 의도상 답은 ④이지만, 문제 설명에 맞는 실제 설정은 위 예시와 같다.

### DHCP와 BOOTP

BOOTP는 RFC 951에 정의된 초기 적재 통신 규약으로, 디스크 없는 장치 등에 IP 정보를 제공하기 위해 개발됐다. DHCP는 BOOTP를 확장해 동적인 임대와 더 다양한 네트워크 설정을 제공한다.

특정 MAC 주소에 고정 IP를 할당하는 DHCP 설정은 다음과 같다.

```text
host ihd_pc {
    hardware ethernet 08:00:07:26:c0:a5;
    fixed-address 192.168.12.22;
}
```

### 원격 데스크톱과 시간 동기화

- NTP는 네트워크를 통해 시스템 시간을 동기화한다.

### TCP Wrapper와 SYN Flooding

독립 데몬의 TCP Wrapper 지원 여부는 `libwrap.so` 링크를 확인한다.

```bash
ldd /path/to/daemon | grep libwrap
```

TCP Wrapper의 호스트 접근 제어 파일은 `/etc/hosts.allow`와 `/etc/hosts.deny`다.

SYN Flooding이 발생하면 서버가 SYN+ACK 이후 마지막 ACK를 받지 못한 반쪽 연결을 많이 유지하므로 `SYN_RECV` 상태가 급증한다.

```bash
ss -ant state syn-recv
netstat -ant | grep SYN_RECV
```

### 보안과 방화벽

반복해서 메모리를 할당하고 해제하지 않는 코드는 메모리 누수를 일으켜 가용 메모리를 고갈시킬 수 있다.

```c
while (1) {
    m = malloc(1000);
}
```

Suricata는 OISF가 개발한 오픈소스 IDS·IPS로 멀티스레딩, Lua 규칙 확장 등을 지원한다.

iptables의 기본 정책은 `-j` 없이 지정한다.

```bash
iptables -P INPUT DROP
iptables -A INPUT -s 192.168.5.4 -j DROP
iptables -L INPUT -n
iptables -t nat -L PREROUTING
```

따라서 `iptables -P INPUT -j DROP`은 잘못된 문법이다.

nftables는 Netfilter 프로젝트가 `iptables`, `ip6tables`, `arptables`, `ebtables`를 대체·통합하기 위해 만든 방화벽 프레임워크다.

```bash
nft list ruleset
```

### 가상화와 컨테이너
