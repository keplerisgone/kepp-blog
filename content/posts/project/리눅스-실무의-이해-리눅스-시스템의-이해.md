## 리눅스와 하드웨어

### 컴퓨터의 구성 요소

| 구성 요소 | 역할 | 예시 |
|---|---|---|
| CPU | 명령 해석·연산과 시스템 제어 | ALU, 제어장치, 레지스터 |
| 주기억장치 | 실행 중인 명령과 데이터 저장 | RAM, ROM |
| 입력장치 | 외부 데이터를 컴퓨터에 전달 | 키보드, 마우스, OCR, OMR |
| 출력장치 | 처리 결과를 사용자에게 전달 | 모니터, 프린터, HMD |
| 보조기억장치 | 대용량 데이터를 비휘발성으로 저장 | HDD, SSD, 광학 디스크 |

#### CPU

- 레지스터: CPU 내부의 가장 빠르고 작은 임시 저장장치
- ALU(Arithmetic Logic Unit): 산술·논리·비교 연산
- 제어장치(Control Unit): 명령을 해석하고 각 장치의 동작을 제어

#### 주기억장치

| 종류 | 특성 | 주요 용도 |
|---|---|---|
| DRAM | 집적도가 높고 비교적 느림, 주기적인 재충전 필요 | 주 메모리 |
| SRAM | 빠르고 비싸며 집적도가 낮음, 재충전 불필요 | CPU 캐시 |
| ROM | 전원이 꺼져도 내용 유지 | 펌웨어 저장 |

ROM 계열은 기록 방식에 따라 Mask ROM, PROM, EPROM, EEPROM·Flash 등으로 나뉜다. 현대 PC의 UEFI 펌웨어는 일반적으로 플래시 메모리에 저장된다.

#### 입력장치 구분

- OMR(Optical Mark Reader): 답안지처럼 표시된 마크 판독
- OCR(Optical Character Recognition): 인쇄·필기 문자를 문자 데이터로 변환
- MICR(Magnetic Ink Character Recognition): 자기 잉크로 인쇄된 문자 판독

### Linux 설치 전 하드웨어 확인

#### CPU

- 배포판이 CPU 아키텍처를 지원하는지 확인한다.
- 대표 아키텍처: x86-64, ARM64, RISC-V, PowerPC 등
- 가상 머신을 사용할 경우 Intel VT-x 또는 AMD-V 같은 하드웨어 가상화 기능도 확인한다.
- 병렬성(Parallelism)은 여러 코어·프로세서에서 실제 계산을 동시에 수행하는 것이고, 동시성(Concurrency)은 여러 작업의 진행이 시간상 겹치는 개념이다.

#### 메인보드와 펌웨어

- 칩셋, 저장장치 컨트롤러와 네트워크 장치 지원 여부 확인
- 설치·부팅 문제가 있으면 UEFI 설정과 펌웨어 업데이트 확인
- Secure Boot, 저장장치 모드와 부팅 순서 확인

#### 메모리

- 배포판과 실행할 서비스의 최소·권장 용량 확인
- 64비트 환경에서는 32비트보다 넓은 주소 공간을 사용할 수 있다.
- 지원 가능한 최대 메모리는 CPU뿐 아니라 메인보드와 배포판·커널 설정에도 좌우된다.
- swap은 메모리 부족을 보완하지만 RAM을 대체할 만큼 빠르지는 않다.

#### 저장장치

Linux에서는 저장장치도 장치 파일로 표현한다.

| 장치 | 일반적인 이름 예 |
|---|---|
| SATA·SAS·SCSI·USB 저장장치 | `/dev/sda`, `/dev/sdb` |
| NVMe SSD | `/dev/nvme0n1` |
| 오래된 IDE 장치 | `/dev/hda` |

장치명은 검색 순서에 따라 바뀔 수 있으므로 영구 설정에는 UUID나 `/dev/disk/by-*` 링크를 사용하는 편이 안전하다.

#### 그래픽·네트워크·입력장치

```bash
lspci              # PCI 장치 확인
lspci | grep -Ei 'vga|3d|display'
lspci | grep -i ethernet
lsusb              # USB 장치 확인
```

- 일반적인 장치는 커널 내장 드라이버로 동작한다.
- 최신 GPU, Wi-Fi와 특수 장치는 별도 펌웨어나 제조사 드라이버가 필요할 수 있다.
- 네트워크 설치 전 IP 주소, 프리픽스·넷마스크, 게이트웨이와 DNS 정보를 확인한다.

## RAID

RAID(Redundant Array of Independent Disks)는 여러 디스크를 하나의 논리 장치로 묶어 성능, 용량 또는 장애 허용성을 높이는 기술이다.

- Striping: 데이터를 여러 디스크에 나누어 기록
- Mirroring: 같은 데이터를 여러 디스크에 복제
- Parity: 손실된 데이터를 계산해 복구하기 위한 정보

RAID는 백업이 아니다. 실수로 삭제하거나 손상된 데이터도 함께 반영될 수 있으므로 별도 백업이 필요하다.

### RAID 레벨 비교

`N`은 같은 크기의 디스크 수, `S`는 가장 작은 디스크의 용량이다.

| 레벨 | 구성 | 최소 디스크 | 사용 가능 용량 | 장애 허용 | 핵심 |
|---|---|---:|---:|---:|---|
| RAID 0 | Striping | 2 | `N × S` | 0개 | 빠르지만 디스크 하나만 고장 나도 전체 손실 |
| RAID 1 | Mirroring | 2 | 보통 `S` | 미러당 1개 | 안정적이지만 2개 구성의 공간 효율 50% |
| RAID 2 | 비트 Striping + Hamming ECC | 다수 | 구성에 따라 다름 | 구성에 따라 다름 | 현재 거의 사용하지 않음 |
| RAID 3 | 바이트 Striping + 전용 Parity | 3 | `(N-1) × S` | 1개 | 전용 패리티 디스크 사용, 거의 사용하지 않음 |
| RAID 4 | 블록 Striping + 전용 Parity | 3 | `(N-1) × S` | 1개 | 패리티 디스크의 쓰기 병목 |
| RAID 5 | 블록 Striping + 분산 Parity | 3 | `(N-1) × S` | 1개 | 성능·용량·안정성의 균형 |
| RAID 6 | 블록 Striping + 이중 분산 Parity | 4 | `(N-2) × S` | 2개 | RAID 5보다 안전하지만 쓰기 비용 증가 |
| RAID 0+1 | Stripe 묶음을 Mirror | 4 | `N/2 × S` | 구성에 따라 다름 | 한 Stripe 묶음 장애 후 허용성 감소 |
| RAID 1+0 | Mirror 묶음을 Stripe | 4 | `N/2 × S` | 미러별 1개 가능 | RAID 0+1보다 일반적으로 복구와 장애 허용성이 좋음 |

RAID 10은 RAID 1+0을 뜻한다. 교재에 나오는 RAID 5+3 같은 표기는 표준 RAID 레벨이라기보다 여러 RAID 구성을 중첩한 특수 구성으로 이해한다.

### RAID 선택 기준

- 최대 성능, 데이터 보호 불필요: RAID 0
- 단순한 이중화: RAID 1
- 용량 효율과 1개 디스크 장애 허용: RAID 5
- 대용량 배열에서 2개 디스크 장애 허용: RAID 6
- 높은 성능과 안정성: RAID 10

패리티는 장애 복구 정보이며 백업 복사본은 아니다. RAID 5·6은 고장 난 디스크를 교체한 뒤 재구축하는 동안 성능이 낮아지고 추가 장애 위험이 커질 수 있다.

## 디스크 인터페이스

| 인터페이스 | 전송 방식 | 주요 환경 | 특징 |
|---|---|---|---|
| IDE·PATA | 병렬 | 구형 PC | 40핀 리본 케이블, 현재 거의 사용하지 않음 |
| SATA | 직렬 | PC, 일반 서버 | 보급형 저장장치의 대표 규격 |
| Parallel SCSI | 병렬 | 구형 서버·워크스테이션 | 안정성과 장치 확장성, 현재는 감소 |
| SAS | 직렬 | 서버·데이터센터 | SCSI 명령 체계, 고성능·신뢰성·확장성 |

### SATA 세대별 링크 속도

| 세대 | 이론상 링크 속도 | 흔히 부르는 이름 |
|---|---:|---|
| SATA 1 | 1.5 Gbit/s | SATA 150 |
| SATA 2 | 3 Gbit/s | SATA 300 |
| SATA 3 | 6 Gbit/s | SATA 600 |

링크 속도는 인코딩 오버헤드를 포함하므로 실제 데이터 전송률은 표기값보다 낮다.

### SATA와 SAS

- SATA: 가격과 범용성을 중시하는 PC·일반 서버용
- SAS: 이중 포트, 확장성, 신뢰성과 연속 운용을 중시하는 기업용
- SAS 컨트롤러는 보통 SATA 드라이브도 연결할 수 있지만, SATA 컨트롤러에는 SAS 드라이브를 연결할 수 없다.

NVMe는 PCI Express 위에서 동작하며 SATA·SAS와 다른 현대적인 SSD 인터페이스다.

## 시험 핵심

- CPU 구성: 레지스터, ALU, 제어장치
- DRAM은 주 메모리, SRAM은 캐시, ROM·Flash는 비휘발성 펌웨어 저장
- OMR은 마크, OCR은 문자, MICR은 자기 잉크 문자 판독
- SATA·SCSI 계열은 보통 `/dev/sdX`, NVMe는 `/dev/nvme0n1`
- RAID 0은 성능만, RAID 1은 Mirroring, RAID 5는 분산 Parity 1개, RAID 6은 Parity 2개
- RAID 10은 Mirror 후 Stripe이며 RAID 0+1보다 일반적으로 장애 대응에 유리
- PATA·SCSI는 병렬, SATA·SAS는 직렬

## 리눅스의 구조

### 부트 매니저

부트 매니저(Boot Manager)는 디스크에 저장된 운영체제의 커널을 메모리에 적재하는 프로그램으로, 부트로더(Boot Loader)라고도 한다.

#### 부팅 흐름

- BIOS/MBR 환경: `POST → MBR의 부트 코드 → GRUB → 커널·initramfs → systemd(PID 1)` 순으로 진행된다.
- 전통적인 MBR은 디스크의 첫 섹터에 위치하며 크기가 512바이트로 제한된다. 따라서 작은 1단계 코드가 파일 시스템을 해석할 수 있는 다음 단계 부트로더를 호출한다.
- UEFI/GPT 환경에서는 펌웨어가 EFI 시스템 파티션(ESP)의 실행 파일을 직접 불러오므로 MBR 방식의 제약을 받지 않는다.

| 종류 | 특징 | 주요 설정 파일 |
| --- | --- | --- |
| LILO | 오래된 리눅스 부트로더. 설정 변경 후 `lilo`를 실행해 MBR에 다시 기록해야 함 | `/etc/lilo.conf` |
| GRUB Legacy | 대화형 메뉴와 명령행, 네트워크 부팅 지원 | `/boot/grub/grub.conf` 또는 `menu.lst` |
| GRUB2 | 현재 널리 사용하며 BIOS·UEFI, GPT, RAID, LVM과 여러 파일 시스템을 지원 | 아래 참고 |

#### GRUB2 사용과 설정

- 메뉴에서 방향키와 `Enter`로 부팅 항목을 선택한다.
- `e`는 선택 항목의 커널 인자를 임시 편집하고, `c`는 GRUB 명령행으로 진입한다. 편집 후 `Ctrl`+`x` 또는 `F10`으로 부팅한다.
- 메뉴에서 바꾼 값은 해당 부팅에만 적용되며 설정 파일에는 저장되지 않는다.
- 원본 설정은 `/etc/default/grub`와 `/etc/grub.d/`에 있다. 이를 바탕으로 생성되는 `/boot/grub2/grub.cfg`(레드햇 계열) 또는 `/boot/grub/grub.cfg`(데비안 계열)는 직접 수정하지 않는다.

```bash
# 레드햇 계열
grub2-mkconfig -o /boot/grub2/grub.cfg

# 데비안·우분투 계열
update-grub
```

| `/etc/default/grub` 항목 | 의미 |
| --- | --- |
| `GRUB_TIMEOUT` | 메뉴에서 사용자 입력을 기다리는 시간 |
| `GRUB_DEFAULT` | 기본 부팅 항목의 번호·이름 또는 `saved` |
| `GRUB_CMDLINE_LINUX` | 모든 리눅스 항목에 전달할 커널 매개변수 |
| `GRUB_DISABLE_SUBMENU` | 하위 메뉴 사용 여부 |
| `GRUB_DISABLE_RECOVERY` | `true`이면 복구 메뉴 항목을 생성하지 않음 |

저장형 기본 항목은 `grub2-set-default`로 지정하고 `grub2-editenv list`로 확인한다. GRUB2 메뉴 편집을 보호하려면 `grub2-mkpasswd-pbkdf2`로 해시를 만든 뒤 `/etc/grub.d/40_custom`에 `set superusers`와 `password_pbkdf2`를 설정하고 `grub.cfg`를 다시 생성한다. 이는 부트 메뉴를 보호하는 기능이며 디스크 자체를 암호화하지는 않는다.

### 주요 디렉터리 구조

FHS(File System Hierarchy Standard)는 배포판 사이에서 디렉터리의 용도를 일관되게 유지하기 위한 표준이다.

| 경로 | 용도 |
| --- | --- |
| `/` | 모든 파일과 디렉터리의 출발점인 루트 디렉터리 |
| `/boot` | 커널, initramfs, 부트로더 관련 파일 |
| `/dev` | 디스크·터미널 등 장치를 나타내는 장치 파일 |
| `/etc` | 시스템 전역 설정 파일과 초기화 설정 |
| `/home` | 일반 사용자의 홈 디렉터리 |
| `/root` | `root` 사용자의 홈 디렉터리 |
| `/run` | 부팅 후 생성되는 PID·소켓 등 휘발성 런타임 데이터 |
| `/tmp` | 프로그램이 만드는 임시 파일. 일반적으로 모든 사용자가 쓰며 Sticky Bit 적용 |
| `/usr` | 사용자 명령, 라이브러리, 헤더와 공유 데이터 |
| `/var` | 로그·스풀·캐시처럼 실행 중 크기가 변하는 데이터 |
| `/proc` | 프로세스와 커널 상태를 보여 주는 가상 파일 시스템 |
| `/sys` | 장치와 커널 객체를 보여 주는 `sysfs` 가상 파일 시스템 |
| `/media` | 이동식 매체의 자동 마운트 지점 |
| `/mnt` | 관리자가 임시로 파일 시스템을 마운트하는 지점 |
| `/opt` | 별도로 설치하는 응용 프로그램 패키지 |

전통적으로 `/bin`에는 필수 사용자 명령, `/sbin`에는 관리 명령, `/lib`에는 필수 라이브러리가 위치했다. 현대 배포판은 이 경로들을 각각 `/usr/bin`, `/usr/sbin`, `/usr/lib`로 연결하는 **usr merge** 구성을 흔히 사용한다. 주요 하위 경로는 다음과 같다.

- `/var/log`: 로그, `/var/spool`: 처리 대기 데이터, `/var/tmp`: 재부팅 후에도 유지할 수 있는 임시 파일
- `/usr/include`: C/C++ 헤더, `/usr/src`: 커널 등 소스 코드
- `/lib/modules`: 설치된 커널의 모듈

### 부팅과 셧다운

부팅은 전원을 켠 뒤 운영체제를 사용할 수 있는 상태로 만드는 과정이다.

```text
펌웨어·POST → 부트로더 → 커널·initramfs → init 또는 systemd → 서비스 → 로그인 프롬프트
```

전통적인 SysV init은 실행 레벨에 따라 초기화 스크립트를 실행한다. 현대의 systemd에서는 이에 대응하는 target을 사용한다.

| 실행 레벨 | SysV 의미 | systemd 대응 target |
| --- | --- | --- |
| 0 | 시스템 종료 | `poweroff.target` |
| 1 | 단일 사용자·복구 모드 | `rescue.target` |
| 2 | 배포판별 다중 사용자 모드 | `multi-user.target` |
| 3 | 네트워크를 지원하는 텍스트 다중 사용자 모드 | `multi-user.target` |
| 4 | 미사용 또는 사용자 정의 | `multi-user.target` |
| 5 | 그래픽 다중 사용자 모드 | `graphical.target` |
| 6 | 재부팅 | `reboot.target` |

#### 로그인과 로그아웃

| 파일 | 표시 시점 |
| --- | --- |
| `/etc/issue` | 로컬 로그인 전 |
| `/etc/issue.net` | 원격 로그인 전. 실제 사용 여부는 해당 서비스 설정에 따름 |
| `/etc/motd` | 인증에 성공한 뒤 |

- 터미널에서는 `exit`, `logout` 또는 `Ctrl`+`d`로 세션을 끝낸다.
- 셸의 `TMOUT` 값을 초 단위로 설정하면 입력이 없는 세션을 자동 종료할 수 있다.

#### 종료와 재시작

```bash
systemctl poweroff          # 전원 끄기
systemctl reboot            # 재부팅
shutdown -h now             # 즉시 종료
shutdown -r +5              # 5분 뒤 재부팅
shutdown -c                 # 예약 취소
```

`halt`, `poweroff`, `reboot`, `init 0`, `init 6`도 시험에서 다루는 전통적인 명령이다. 파일 시스템 손상을 막기 위해 전원을 직접 차단하지 말고 정상 종료 절차를 사용한다.

### systemd

systemd는 SysV init을 대체하는 시스템·서비스 관리자이며 일반적으로 PID 1로 실행된다. 의존성이 없는 유닛은 병렬로 시작하고, 소켓·장치·경로 요청에 따라 서비스를 필요할 때 실행할 수 있다.

#### 유닛 유형

| 유형 | 확장자 | 용도 |
| --- | --- | --- |
| Service | `.service` | 서비스와 데몬 |
| Target | `.target` | 여러 유닛을 묶는 동기화 지점. 실행 레벨과 유사 |
| Socket | `.socket` | 소켓 기반 활성화 |
| Timer | `.timer` | 시간 기반 활성화 |
| Mount·Automount | `.mount`, `.automount` | 파일 시스템 마운트와 자동 마운트 |
| Path | `.path` | 파일·디렉터리 변경 감시 |
| Device | `.device` | 커널이 인식한 장치 |
| Swap | `.swap` | 스왑 장치·파일 |

동일한 이름의 유닛이 여러 곳에 있으면 관리자 설정이 공급자 설정을 덮어쓴다.

1. `/etc/systemd/system/`: 관리자가 작성·수정한 영구 설정
2. `/run/systemd/system/`: 실행 중 임시로 생성된 설정
3. `/usr/lib/systemd/system/`: 패키지가 설치한 공급자 설정(일부 배포판은 `/lib/systemd/system/`)

유닛 파일은 보통 다음 섹션으로 구성된다.

- `[Unit]`: `Description`, `After`, `Requires`, `Wants` 등 공통 정보와 관계. `After`는 시작 순서만 정한다.
- `[Service]` 등 유형별 섹션: `ExecStart`, `ExecStop`처럼 해당 유닛의 동작을 정의한다.
- `[Install]`: `WantedBy`, `RequiredBy` 등 `enable`할 때 사용할 정보를 정의한다.

#### 주요 명령

| 작업 | 명령 |
| --- | --- |
| 시작·중지·재시작 | `systemctl start|stop|restart name.service` |
| 실행 중일 때만 재시작 | `systemctl try-restart name.service` |
| 설정 다시 읽기 | `systemctl reload name.service` |
| 상태 확인 | `systemctl status name.service` |
| 부팅 시 자동 시작·해제 | `systemctl enable|disable name.service` |
| 즉시 시작하면서 자동 시작 | `systemctl enable --now name.service` |
| 기본 target 확인·변경 | `systemctl get-default`, `systemctl set-default name.target` |
| 현재 target 전환 | `systemctl isolate name.target` |
| 복구·응급 모드 | `systemctl rescue`, `systemctl emergency` |

`enable`은 부팅 시 실행될 링크를 만드는 작업으로 현재 서비스를 시작하는 것과 다르다. 변경된 유닛 파일을 다시 읽힐 때는 `systemctl daemon-reload`를 사용한다. SSH로 접근 가능한 원격 호스트는 `systemctl -H user@host status name.service`처럼 제어할 수도 있다.

### 파일 시스템의 이해

파일 시스템은 디스크의 블록을 파일과 디렉터리로 조직하고, 캐시·메타데이터·오류 복구 기능을 제공하는 계층이다.

#### ext 계열의 기본 구조

ext2의 디스크는 부트 영역 뒤에 여러 블록 그룹이 이어지는 형태다. 각 블록 그룹은 다음 정보를 가진다.

| 구성 요소 | 역할 |
| --- | --- |
| 슈퍼 블록 | 블록 크기, 전체 블록·inode 수 등 파일 시스템 전체 정보 |
| 그룹 디스크립터 | 각 블록 그룹의 비트맵·inode 테이블 위치와 여유 공간 정보 |
| 블록 비트맵 | 데이터 블록의 사용 여부 |
| inode 비트맵 | inode의 사용 여부 |
| inode 테이블 | 파일별 inode 집합 |
| 데이터 블록 | 디렉터리 항목과 실제 파일 내용 |

inode에는 파일 형식·권한, UID/GID, 크기, 링크 수, 타임스탬프와 데이터 블록 위치가 기록된다. **파일 이름은 inode가 아니라 디렉터리 항목에 저장**되며, 디렉터리는 이름을 inode 번호에 대응시킨다. ext 계열에서 루트 디렉터리는 inode 2를 사용한다.

고전적인 ext2 inode는 15개 블록 포인터를 가지며 12개는 직접 블록, 나머지는 단일·이중·삼중 간접 블록을 가리킨다. ext4는 큰 파일을 효율적으로 나타내기 위해 연속 블록 범위를 기록하는 extent를 주로 사용한다.

#### 로컬 파일 시스템

| 파일 시스템 | 핵심 특징 |
| --- | --- |
| ext2 | 저널링이 없는 ext 계열. 비정상 종료 후 `fsck` 시간이 길 수 있음 |
| ext3 | ext2 호환 구조에 저널링을 추가 |
| ext4 | extent, 지연 할당, 멀티블록 할당, 저널 체크섬을 지원하는 대표 범용 파일 시스템 |
| XFS | 고성능 64비트 저널링 파일 시스템. 대용량·병렬 I/O와 온라인 확장에 강함 |
| Btrfs | Copy-on-Write, 스냅샷·서브볼륨, 체크섬, 압축과 다중 장치 기능 제공 |
| ZFS | 파일 시스템과 볼륨 관리를 결합하고 CoW, 체크섬, 스냅샷, 자동 복구 기능 제공 |
| ReiserFS·JFS | 각각 Reiser 계열과 IBM이 개발한 저널링 파일 시스템으로 현재는 주로 기존 시스템에서 접함 |

파일·파일 시스템의 최대 크기는 파일 시스템 버전, 블록 크기와 구현에 따라 달라지므로 오래된 교재의 단일 수치보다 구조와 특징을 우선해 기억한다.

#### 그 밖의 파일 시스템

| 종류 | 용도 |
| --- | --- |
| Raw partition | 파일 시스템 없이 블록 장치를 직접 사용. 관리가 어렵지만 오버헤드가 적음 |
| OCFS2 | 여러 노드가 공유 저장소에 접근하는 범용 클러스터 파일 시스템 |
| VFAT | FAT 계열과 호환되는 이동식 매체용 파일 시스템 |
| ISO 9660 | CD-ROM 표준 파일 시스템 |
| NFS | 유닉스·리눅스의 네트워크 파일 공유 |
| SMB/CIFS | 윈도우 계열과의 네트워크 파일 공유 |
| procfs·sysfs | 디스크에 저장되지 않고 프로세스·커널·장치 정보를 제공하는 가상 파일 시스템 |

#### 시험 핵심

- GRUB2 메뉴의 `e`는 임시 편집, `c`는 명령행이며 영구 설정은 원본 파일 수정 후 `grub2-mkconfig`로 생성한다.
- `/proc`, `/sys`는 가상 파일 시스템이고 `/run`은 부팅 후의 휘발성 런타임 데이터다.
- SysV 실행 레벨 3은 텍스트 다중 사용자, 5는 그래픽, 0은 종료, 6은 재부팅이다.
- `systemctl enable`은 자동 시작 설정, `start`는 현재 시작이며 `enable --now`는 둘을 함께 수행한다.
- 디렉터리는 파일 이름과 inode 번호의 대응을 저장하고 inode는 권한·소유자·블록 위치 등 메타데이터를 저장한다.
- ext3의 핵심은 저널링, ext4의 핵심은 extent와 지연·멀티블록 할당이다.
